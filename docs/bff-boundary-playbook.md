# BFF Boundary Playbook

이 문서는 BFF를 사용할 때 도메인 경계를 훼손하지 않는 기준을 정리합니다.

<br/>
<br/>

## BFF의 책임

- 채널/화면 최적화 입력을 애플리케이션 유스케이스 입력으로 변환
- 다중 Query 결과를 하나의 응답으로 조합
- 인증/권한 컨텍스트를 유스케이스 호출 경계로 전달

BFF는 **도메인 정책 소유자**가 아닙니다.

<br/>
<br/>

## Query 중심 + 제한적 Command 위임

### 허용

- 기존 도메인 Command를 위임 호출
- 요청 포맷 변환/검증/에러 매핑
- 트레이싱/관찰성 메타데이터 부착

### 금지

- BFF에서 repository/Entity 직접 접근
- BFF에서 신규 상태 전이 정책 정의
- 트랜잭션/보상 정책을 BFF에 고정

<br/>
<br/>

## BFF Command 위임 체크리스트

- 도메인 상태 전이 규칙이 원 모듈 Handler에 남아 있는가?
- outbox/event 기록이 도메인 모듈 내부에서 수행되는가?
- 실패/보상 정책이 Saga 또는 도메인 경계에 정의되어 있는가?
- BFF 코드를 제거해도 도메인 유스케이스가 독립 실행 가능한가?

<br/>
<br/>

## Reader 계약과의 연결

- 도메인 간 조회는 Reader 계약으로 분리
- BFF는 Reader를 조합하되, Reader 계약의 페이징/카운트 의미를 변경하지 않음
- 응답 포맷 차이는 BFF 응답 DTO에서만 처리
