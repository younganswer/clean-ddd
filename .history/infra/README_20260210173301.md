# infra

## AWS (on-demand) 배포 개요

- Backend: API Gateway(HTTP API) + Lambda 2개
  - HTTP Lambda: [apps/api/src/lambda/http.handler.ts](../apps/api/src/lambda/http.handler.ts)
  - SQS Consumer Lambda: [apps/api/src/lambda/sqs.handler.ts](../apps/api/src/lambda/sqs.handler.ts)
- Queue: SQS FIFO 1개 + DLQ(FIFO)

## SAM 템플릿

- 파일: [infra/sam/template.yaml](sam/template.yaml)

### 전제

- `apps/api`는 `pnpm --filter api build`로 `dist/`가 생성되어 있어야 합니다.
- Neon pooled URL은 파라미터로 주입합니다.

### 배포(예시)

```bash
cd infra/sam
sam build
sam deploy --guided
```

## Frontend 배포(S3 정적 + CloudFront)

비용 최소/운영 단순 목적이라면 다음 순서를 권장합니다.

1. `apps/admin` 빌드: `pnpm --filter admin build`

- 정적 결과물: `apps/admin/out/`

2. S3 버킷: 정적 호스팅(또는 OAC로 CloudFront만 공개)
3. CloudFront: 캐시 정책 + SPA fallback(필요 시)
4. 배포 파이프라인: GitHub Actions(OIDC)로 `aws s3 sync` + CloudFront invalidation

※ Next.js App Router 기반에서 완전 정적 export가 가능한지(동적 기능 사용 여부)를 먼저 고정해야 합니다.

S3 업로드 예시:

```bash
cd apps/admin
aws s3 sync out s3://YOUR_BUCKET --delete
```
