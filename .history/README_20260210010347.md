# clean-ddd

주문 도메인을 예시로 DDD + Clean Architecture를 적용한 샘플 서비스입니다.

## 목표

- Backend: NestJS + MikroORM + Neon(PostgreSQL)
- Event: Outbox 패턴 + 단일 SQS FIFO 큐(`OutboxDispatchQueue.fifo`)
- Compute: AWS on-demand(HTTP: API Gateway + Lambda, Async: SQS + Lambda)
- Frontend: Next.js(Admin) → S3 정적 배포 + CloudFront

## 저장소 구조

- apps/backend: 백엔드(NestJS)
- apps/frontend: 어드민(Next.js)
- packages/contracts: API 계약(OpenAPI 등) 및 공용 타입(도메인 객체는 공유하지 않음)

## 개발 환경

이 워크스페이스는 전역 `pnpm` 설치 없이도 동작하도록 `shims/pnpm`을 제공합니다.

```bash
export PATH="$PWD/shims:$PATH"
pnpm -v
```

## 로컬 실행(개발)

### 1) 원클릭 실행(권장)

```bash
./shims/pnpm dev:local
```

기본 포트:

- API: http://localhost:3000/api/v1
- Admin(개발 서버): http://localhost:3001

추가 명령:

```bash
# Postgres 접속 + SQS 큐 존재 확인(10초 간격 3회 재시도)
./shims/pnpm health:local

# 인프라 → 헬스체크 → 마이그레이션 → 서버 기동 → HTTP 플로우까지 스모크 테스트
./shims/pnpm smoke:local
```

### 2) 인프라만 기동/정리

```bash
./shims/pnpm infra:up
./shims/pnpm infra:down

# Postgres 데이터까지 초기화(pruning)
./shims/pnpm infra:prune
```

### 3) SQS(LocalStack) 큐 URL(참고)

```text
http://localhost:4566/000000000000/OutboxDispatchQueue.fifo
```

참고: LocalStack을 `http://localhost:4566`로 사용할 때는 기본 리전 `us-east-1` 기준으로 동작합니다.

또한 LocalStack의 SQS FIFO 큐는 `DelaySeconds`를 허용하지 않는 경우가 있어, 로컬 개발/스모크에서는 `SQS_DISABLE_DELAY_SECONDS=true`로 지연 전송을 setTimeout 기반으로 우회합니다(프로덕션 AWS SQS에서는 `DelaySeconds`를 그대로 사용).

## 프로덕션(Neon) 체크/마이그레이션

Neon 연결은 환경변수에 의존합니다. (둘 다 없으면 실패)

```bash
# 연결 문자열 유효성/접속 확인(10초 간격 3회 재시도)
export DATABASE_URL_DIRECT='...'
export DATABASE_URL_POOLED='...'
./shims/pnpm prod:check

# 마이그레이션 실행(Neon direct URL 우선)
./shims/pnpm prod:migrate
```

## DB 마이그레이션

Neon direct URL을 우선 사용합니다.

```bash
export PATH="$PWD/shims:$PATH"
cd apps/backend
export DATABASE_URL_DIRECT='...'
pnpm db:migration:create
pnpm db:migrate
```
