# clean-ddd

주문 도메인을 예시로 DDD + Clean Architecture를 적용한 샘플 서비스입니다.

## 목표

- Backend: NestJS + MikroORM + Neon(PostgreSQL)
- Event: Outbox 패턴 + 단일 SQS FIFO 큐(`OutboxDispatchQueue.fifo`)
- Compute: AWS on-demand(HTTP: API Gateway + Lambda, Async: SQS + Lambda)
- Frontend: Next.js(Admin) → S3 정적 배포 + CloudFront

## 저장소 구조

- apps/backend: 백엔드(NestJS)
- apps/frontend: 어드민(Next.js)
- packages/contracts: API 계약(OpenAPI 등) 및 공용 타입(도메인 객체는 공유하지 않음)

## 개발 환경

이 워크스페이스는 Corepack을 통해 `pnpm` 버전을 고정합니다. (루트 `package.json`의 `packageManager` 참고)

필수:

```bash
corepack enable
corepack pnpm -v
corepack pnpm install
```

## 로컬 실행(개발) — PM2 기반(공식)

`pnpm dev` 하나로 인프라 + 백엔드(PM2) + 프론트(Next dev)를 모두 띄웁니다.

```bash
corepack pnpm dev
```

기본 포트:

- API: http://localhost:3000/api/v1
- Admin(개발 서버): http://localhost:3001

PM2 프로세스:

- `clean-ddd-api` / `clean-ddd-cron` / `clean-ddd-queue` / `clean-ddd-admin`

로그:

- apps/backend/logs/*.log

### 변경 반영(공식) — PM2 reload

백엔드 코드 변경 후 아래 명령으로 재빌드 + 무중단 reload 합니다.

```bash
corepack pnpm reload:pm2
```

참고: 프론트는 Next dev라서 저장 시 즉시 반영되지만, 백엔드는 빌드 산출물(`dist/src/main.js`)을 실행하므로 `reload:pm2`가 필요합니다.

### 중지

```bash
corepack pnpm stop:pm2
```

### 2) 인프라만 기동/정리

```bash
corepack pnpm infra:up
corepack pnpm infra:down

# Postgres 데이터까지 초기화(pruning)
corepack pnpm infra:prune
```

### 3) 헬스체크/스모크(선택)

```bash
# Postgres 접속 + SQS 큐 존재 확인(10초 간격 3회 재시도)
corepack pnpm health:local

# 인프라 → 헬스체크 → 마이그레이션 → 서버 기동 → HTTP 플로우까지 스모크 테스트
corepack pnpm smoke:local
```

### 3) SQS(LocalStack) 큐 URL(참고)

```text
http://localhost:4566/000000000000/OutboxDispatchQueue.fifo
```

참고: LocalStack을 `http://localhost:4566`로 사용할 때는 기본 리전 `us-east-1` 기준으로 동작합니다.

또한 LocalStack의 SQS FIFO 큐는 `DelaySeconds`를 허용하지 않는 경우가 있어, 로컬 개발/스모크에서는 `SQS_DISABLE_DELAY_SECONDS=true`로 지연 전송을 setTimeout 기반으로 우회합니다(프로덕션 AWS SQS에서는 `DelaySeconds`를 그대로 사용).

## 프로덕션(Neon) 체크/마이그레이션

Neon 연결은 환경변수에 의존합니다. (둘 다 없으면 실패)

```bash
# 연결 문자열 유효성/접속 확인(10초 간격 3회 재시도)
export DATABASE_URL_DIRECT='...'
export DATABASE_URL_POOLED='...'
corepack pnpm prod:check

# 마이그레이션 실행(Neon direct URL 우선)
corepack pnpm prod:migrate

# (옵션) PM2 기반으로 마이그레이션 실행 (워크스페이스 devDependency의 pm2 사용)
corepack pnpm prod:migrate:pm2
```

## DB 마이그레이션

Neon direct URL을 우선 사용합니다.

```bash
cd apps/backend
export DATABASE_URL_DIRECT='...'
corepack pnpm db:migration:create
corepack pnpm db:migrate

# (옵션) PM2로 1회성 마이그레이션 실행 (워크스페이스 devDependency의 pm2 사용)
corepack pnpm db:migrate:pm2:local
```

## 워크스페이스 스크립트 실행(유연 처리)

루트의 `build/lint/typecheck/format/test`는 `pnpm -r ... --if-present`로 실행됩니다.

- 예: packages/contracts는 `dev/build/test`가 없기 때문에, 재귀 실행 시 해당 스크립트가 없는 패키지는 자동으로 건너뜁니다.
- 목적: “스크립트 없는/부족한 패키지 때문에 전체 명령이 실패”하는 상황을 방지
